# 单据编号生成器源码分析报告

## 1. 概述

本报告深入分析 InvoiceShelf 系统中单据编号生成器的实现机制。该生成器位于 `app/Services/SerialNumberFormatter.php` 服务类中，为发票（Invoice）、报价单（Estimate）、付款单（Payment）三种业务单据提供编号生成能力。

核心设计包含三种语义的组合：
- **递增语义**：保证编号的连续性和可追溯性
- **随机化语义**：提供不可预测性，防止业务数据泄露
- **可逆混淆**：对外暴露的 URL 安全标识符，隐藏内部自增 ID

## 3. 递增语义分析

### 3.1 两个维度的递增

递增语义通过两个独立的序列实现：

#### 3.1.1 公司全局递增序列 (`sequence_number`)

**核心方法**：`setNextSequenceNumber()`（`app/Services/SerialNumberFormatter.php:118`）

```php
public function setNextSequenceNumber()
{
    $companyId = $this->company;

    $last = $this->model::orderBy('sequence_number', 'desc')
        ->where('company_id', $companyId)
        ->where('sequence_number', '<>', null)
        ->take(1)
        ->first();

    $this->nextSequenceNumber = ($last) ? $last->sequence_number + 1 : 1;

    return $this;
}
```

**关键点**：
1. 查询当前公司下该类型单据的最大 `sequence_number`
2. 若存在则 +1，否则从 1 开始
3. 存储字段：`sequence_number` (mediumInteger, unsigned)

#### 3.1.2 客户维度递增序列 (`customer_sequence_number`)

**核心方法**：`setNextCustomerSequenceNumber()`（`app/Services/SerialNumberFormatter.php:136`）

```php
public function setNextCustomerSequenceNumber()
{
    $customer_id = ($this->customer) ? $this->customer->id : 1;

    $last = $this->model::orderBy('customer_sequence_number', 'desc')
        ->where('company_id', $this->company)
        ->where('customer_id', $customer_id)
        ->where('customer_sequence_number', '<>', null)
        ->take(1)
        ->first();

    $this->nextCustomerSequenceNumber = ($last) ? $last->customer_sequence_number + 1 : 1;

    return $this;
}
```

**关键点**：
1. 在 `company_id` 基础上增加 `customer_id` 过滤条件
2. 每个客户拥有独立的递增序列
3. 存储字段：`customer_sequence_number` (mediumInteger, unsigned)

### 3.2 占位符渲染

在 `generateSerialNumber()`（`app/Services/SerialNumberFormatter.php:185`）中处理递增占位符：

```php
case 'SEQUENCE':
    $value = $value ? $value : 6;
    $serialNumber .= str_pad($this->nextSequenceNumber, $value, 0, STR_PAD_LEFT);
    break;

case 'CUSTOMER_SEQUENCE':
    $serialNumber .= str_pad($this->nextCustomerSequenceNumber, $value, 0, STR_PAD_LEFT);
    break;
```

**特性**：
- 支持自定义补零长度（默认 6 位）
- 左补零保证固定宽度，例如 `000001`
- 格式参数通过 `{{SEQUENCE:6}}` 语法传递

## 4. 随机化语义分析

### 4.1 实现机制

**核心代码**：`generateSerialNumber()` 中的 `RANDOM_SEQUENCE` 分支（`app/Services/SerialNumberFormatter.php:206`）

```php
case 'RANDOM_SEQUENCE':
    $value = $value ? $value : 6;
    $serialNumber .= substr(bin2hex(random_bytes($value)), 0, $value);
    break;
```

### 4.2 技术细节

1. **随机源**：使用 PHP 原生 `random_bytes()` 函数，提供密码学安全的随机数
2. **编码**：通过 `bin2hex()` 转换为十六进制字符串
3. **长度控制**：截取前 N 个字符，保证输出长度与参数一致
4. **字符集**：仅包含 `0-9a-f` 十六进制字符

### 4.3 安全特性

- 不可预测性：防止攻击者通过编号推测业务量或其他信息
- 防碰撞：6 位十六进制有 `16^6 = 16,777,216` 种组合，碰撞概率极低
- 不可推导：无法从一个随机编号推断出相邻编号

## 5. 可逆混淆语义分析

### 5.1 架构设计

可逆混淆通过独立的 Hashids 子系统实现，与序列号生成器解耦。

#### 5.1.1 配置层

**配置文件**：`config/hashids.php`

每个模型类拥有独立的 Hashids 连接配置：

```php
'connections' => [
    Invoice::class => [
        'salt' => Invoice::class.config('app.key'),
        'length' => 20,
        'alphabet' => 'XKAR7m8jD2bqP9OSVeNGiYL465T10zhfWuc3',
    ],
    Estimate::class => [
        'salt' => Estimate::class.config('app.key'),
        'length' => 20,
        'alphabet' => 'yJW2P79M8rCHsVq5zbn1fXl6IUt3dAekGo40',
    ],
    // ... 其他模型
],
```

**关键设计**：
- **Salt 构成**：`类名 + app.key`，确保每个模型、每个部署环境的混淆结果不同
- **固定长度**：20 位字符，隐藏原始 ID 的数量级
- **自定义字母表**：每个模型使用不同的字母表，进一步增强混淆效果
- **URL 安全**：字母表仅包含大小写字母和数字，无特殊字符

#### 5.1.2 核心组件

**HashidsManager**：`app/Hashids/HashidsManager.php`

- 连接池管理：缓存已创建的 Hashids 客户端实例
- 动态解析：按模型类名获取对应配置
- 方法委托：通过 `__call()` 魔术方法委托给底层 Hashids 客户端

**HashidsFactory**：`app/Hashids/HashidsFactory.php`

```php
protected function getClient(array $config): Hashids
{
    return new Hashids($config['salt'], $config['length'], $config['alphabet']);
}
```

### 5.2 使用方式

在各模型的 `create` 方法中调用：

**Invoice 示例**：`app/Models/Invoice.php:344`

```php
$invoice->unique_hash = Hashids::connection(Invoice::class)->encode($invoice->id);
```

**Payment 示例**：`app/Models/Payment.php:171`

```php
$payment->unique_hash = Hashids::connection(Payment::class)->encode($payment->id);
```

### 5.3 可逆性保障

Hashids 算法的核心特性：
- **编码**：`encode(id)` → 混淆字符串
- **解码**：`decode(hash)` → 原始 ID 数组
- **确定性**：相同输入 + 相同配置 → 相同输出
- **双向映射**：可以从 `unique_hash` 还原出原始 `id`

### 5.4 与序列号的关系

| 维度 | sequence_number | unique_hash |
|------|-----------------|-------------|
| 用途 | 业务单据编号 | URL 安全标识符 |
| 语义 | 递增可预测 | 可逆混淆 |
| 暴露范围 | 打印在 PDF 上 | 用于公开链接 |
| 唯一性 | 公司内唯一 | 同模型表内全局唯一 |

## 6. 三种语义的拼装机制

### 6.1 执行流程

编号生成的完整调用链（以 Invoice 创建为例）：

```
Invoice::createInvoice($request)
├── 1. 创建基础记录 (获取自增 id)
├── 2. Hashids 混淆层
│   └── Hashids::connection(Invoice::class)->encode($invoice->id)
│   └── 结果存入 $invoice->unique_hash
├── 3. 序列号生成器初始化
│   ├── setModel($invoice)
│   ├── setCompany($invoice->company_id)
│   ├── setCustomer($invoice->customer_id)
│   └── setNextNumbers()
│       ├── setNextSequenceNumber() → 计算公司全局递增
│       └── setNextCustomerSequenceNumber() → 计算客户维度递增
├── 4. 保存递增序号
│   ├── $invoice->sequence_number = $serial->nextSequenceNumber
│   └── $invoice->customer_sequence_number = $serial->nextCustomerSequenceNumber
└── 5. 生成最终编号 (在别处调用 getNextNumber)
    └── generateSerialNumber($format) → 按格式拼装所有占位符
```

### 6.2 占位符解析引擎

**核心方法**：`getPlaceholders()`（`app/Services/SerialNumberFormatter.php:152`）

```php
public static function getPlaceholders(string $format)
{
    $regex = '/{{([A-Z_]{1,})(?::)?([a-zA-Z0-9_]{1,6}|.{1})?}}/';
    preg_match_all($regex, $format, $placeholders);
    // ... 映射验证后返回
}
```

**正则解析规则**：
- 格式：`{{NAME:PARAM}}` 或 `{{NAME}}`
- `NAME`：占位符类型（必须在 `VALID_PLACEHOLDERS` 中）
- `PARAM`：可选参数（长度、分隔符、日期格式等）

### 6.3 拼装策略

**核心方法**：`generateSerialNumber()`（`app/Services/SerialNumberFormatter.php:185`）

采用 **管道式拼装** 策略：
1. 解析出所有占位符及其参数
2. 按占位符在格式字符串中的出现顺序
3. 逐个调用对应的语义处理器
4. 将处理结果依次拼接

```php
private function generateSerialNumber(string $format)
{
    $serialNumber = '';
    $placeholders = self::getPlaceholders($format);

    foreach ($placeholders as $placeholder) {
        $name = $placeholder['name'];
        $value = $placeholder['value'];

        switch ($name) {
            case 'SEQUENCE':       // 递增语义
            case 'CUSTOMER_SEQUENCE': // 递增语义
            case 'RANDOM_SEQUENCE': // 随机化语义
            case 'DATE_FORMAT':    // 辅助
            case 'CUSTOMER_SERIES': // 辅助
            case 'SERIES':         // 辅助
            case 'DELIMITER':      // 辅助
            default:
                $serialNumber .= $processedValue;
        }
    }

    return $serialNumber;
}
```

### 6.4 典型拼装示例

默认格式定义于 `app/Models/Company.php:246`：

```php
'invoice_number_format' => '{{SERIES:INV}}{{DELIMITER:-}}{{SEQUENCE:6}}',
```

**拼装过程**：

| 占位符 | 参数 | 语义处理器 | 输出 |
|--------|------|-----------|------|
| `SERIES` | `INV` | 字面量输出 | `INV` |
| `DELIMITER` | `-` | 字面量输出 | `-` |
| `SEQUENCE` | `6` | 递增+补零 | `000001` |
| **最终结果** | | | **`INV-000001`** |

**混合随机化的格式示例**：

格式：`{{DATE_FORMAT:Y}}{{RANDOM_SEQUENCE:4}}{{SEQUENCE:4}}`

| 占位符 | 参数 | 输出示例 |
|--------|------|---------|
| `DATE_FORMAT` | `Y` | `2024` |
| `RANDOM_SEQUENCE` | `4` | `a3f7` |
| `SEQUENCE` | `4` | `0042` |
| **最终结果** | | **`2024a3f70042`** |

## 7. 跨租户冲突预防机制

### 7.1 租户模型

本系统采用 **单数据库共享表** 多租户架构，`company_id` 作为租户标识符。

### 7.2 三层防御机制

#### 7.2.1 第一层：查询时的租户过滤

在递增序列计算时，**所有查询都强制带上 `company_id` 条件**：

**全局序列查询**：`app/Services/SerialNumberFormatter.php:122`

```php
$last = $this->model::orderBy('sequence_number', 'desc')
    ->where('company_id', $companyId)  // 关键：租户隔离
    ->where('sequence_number', '<>', null)
    ->take(1)
    ->first();
```

**客户序列查询**：`app/Services/SerialNumberFormatter.php:140`

```php
$last = $this->model::orderBy('customer_sequence_number', 'desc')
    ->where('company_id', $this->company)  // 关键：租户隔离
    ->where('customer_id', $customer_id)
    ->where('customer_sequence_number', '<>', null)
    ->take(1)
    ->first();
```

#### 7.2.2 第二层：编号格式的租户级配置

每个公司可以独立配置编号格式，存储于 `CompanySetting` 中：

```php
$format = CompanySetting::getSetting(
    $settingKey,    // invoice_number_format / estimate_number_format / ...
    $companyId      // 租户标识
);
```

这意味着：
- 公司 A 可以使用 `INV-{SEQUENCE}` 格式
- 公司 B 可以使用 `{DATE_FORMAT}-{RANDOM_SEQUENCE}` 格式
- 两者互不影响

#### 7.2.3 第三层：外键约束与级联删除

数据库层面的防御，见于 `database/migrations/2017_04_12_090759_create_invoices_table.php:37`：

```php
$table->integer('company_id')->unsigned()->nullable();
$table->foreign('company_id')->references('id')->on('companies')->onDelete('cascade');
```

**作用**：
1. 确保 `company_id` 引用的是真实存在的公司
2. 公司删除时级联删除所有关联单据，防止脏数据

### 7.3 调用链中的租户传递

在创建流程中，`company_id` 始终被正确传递：

```php
$serial = (new SerialNumberFormatter)
    ->setModel($invoice)
    ->setCompany($invoice->company_id)  // 从模型获取租户 ID
    ->setCustomer($invoice->customer_id)
    ->setNextNumbers();
```

### 7.4 冲突场景分析

| 场景 | 是否冲突 | 原因 |
|------|---------|------|
| 公司 A 发票 #1 和 公司 B 发票 #1 | 否 | `sequence_number` 均可为 1，但查询与配置都带 `company_id` 隔离 |
| 公司 A 发票 #1 和 公司 A 报价单 #1 | 否 | 不同模型表，独立计数 |
| 公司 A 客户 X 发票 #1 和 公司 A 客户 Y 发票 #1 | 否 | `customer_sequence_number` 按客户隔离 |
| 公司 A 发票 `unique_hash` 和 公司 B 发票 `unique_hash` | 否 | 同一张表的 `id` 本就全局唯一，Hashids 又按模型连接分别配置盐值和字母表 |

## 8. 潜在风险与改进建议

### 8.1 并发安全风险

**当前问题**：递增序列采用「读取最大值 → +1 → 写入」的模式，在高并发场景下存在竞态条件。

**竞态窗口**：
```
T1: 事务A查询 max(sequence_number) → 100
T2: 事务B查询 max(sequence_number) → 100
T3: 事务A写入 sequence_number=101
T4: 事务B写入 sequence_number=101  ← 冲突！
```

**建议改进**：
1. 添加数据库层面的唯一约束：
   ```sql
   ALTER TABLE invoices ADD UNIQUE KEY idx_company_sequence (company_id, sequence_number);
   ```

2. 使用悲观锁或乐观锁：
   ```php
   DB::transaction(function () {
       $last = $this->model::where('company_id', $companyId)
           ->lockForUpdate()  // 悲观锁
           ->max('sequence_number');
   });
   ```

3. 或使用数据库自增序列（如 PostgreSQL 的 SEQUENCE）

### 8.2 随机化语义的碰撞风险

**当前问题**：`RANDOM_SEQUENCE` 生成后未校验唯一性，理论上存在碰撞可能。

**建议改进**：生成后检查是否已存在，若碰撞则重试。

### 8.3 字段长度限制

**当前问题**：`sequence_number` 和 `customer_sequence_number` 定义为 `mediumInteger`，最大值为 16,777,215。

**风险**：对于业务量极大的公司，可能在数年后耗尽。

**建议改进**：考虑升级为 `integer` (20 亿) 或 `bigInteger`。

## 9. 总结

### 9.1 三种语义的定位

| 语义 | 核心价值 | 技术实现 |
|------|---------|---------|
| **递增** | 业务连续性、可审计性 | `MAX() + 1` + 左补零 |
| **随机化** | 防数据泄露、不可预测 | `random_bytes()` + 十六进制编码 |
| **可逆混淆** | URL 安全、隐藏内部 ID | Hashids 算法 + 独立 Salt |

### 9.2 拼装哲学

编号生成器采用 **"声明式格式 + 语义化占位符"** 的设计：
- 用户通过格式字符串声明想要的编号样式
- 系统将占位符解析为独立的语义处理单元
- 按顺序拼装成最终编号

这种设计的优势：
- 灵活性：无需修改代码即可调整编号格式
- 可组合性：多种语义可以自由搭配
- 可扩展性：新增占位符只需添加一个 case 分支

### 9.3 跨租户隔离的本质

跨租户冲突预防的核心是 **"处处携带 company_id"**：
- 查询过滤：`where('company_id', ...)`
- 配置隔离：`getSetting($key, $companyId)`
- 数据约束：外键引用 `companies.id`

这是共享表多租户架构的经典最佳实践。
