# 付款单编号刷新流程深度分析报告

## 1. 概述

本报告针对付款单（Payment）的编号刷新流程进行源码级深度梳理，重点解答以下问题：

1. **客户切换触发重新取号的入口** — 揭示「双入口并行触发」的特殊机制
2. **选中发票后更新的具体状态** — 完整的字段变更清单
3. **客户切换 → 发票列表刷新 → 编号写回**的串联步骤 — 时间轴级别的事件序列
4. **编辑模式与新建模式的行为差异** — 后端逻辑的对比分析

### 3.3 双入口的并行执行

当用户选择客户时，以下事件**几乎同时发生**：

```
用户选择客户
    │
    ├─→ v-model 绑定更新：paymentStore.currentPayment.customer_id = 新客户ID
    │      │
    │      └─→ watchEffect 监听触发 onCustomerChange(新客户ID)
    │           （见 L371-L379）
    │
    └─→ @update:modelValue 事件触发 selectNewCustomer(新客户ID)
         （见 L91-L93）
```

### 3.4 入口一：selectNewCustomer(id) — 负责编号刷新

**代码位置** [payments/Create.vue:L519-L530](file:///d:/fz/0601-1/solo-dogfeeding/code/22-InvoiceShelf/resources/scripts/admin/views/payments/Create.vue#L519-L530)

```javascript
function selectNewCustomer(id) {
  let params = {
    userId: id,                    // 传给后端计算 CUSTOMER_SEQUENCE
  }
  if (route.params.id) {
    params.model_id = route.params.id  // 编辑模式传入，保留原有序号
  }

  // 先清空与原发票相关的状态
  paymentStore.currentPayment.invoice_id = null
  selectedInvoice.value = null
  paymentStore.currentPayment.amount = 0
  invoiceList.value = []

  // 关键：重新获取编号并立即写回
  paymentStore.getNextNumber(params, true)  // setState=true → 直接写回 payment_number
}
```

**核心职责**：
1. 清空与原客户发票相关的状态（发票选择、金额、列表）
2. 调用 `getNextNumber(params, true)` 刷新 `payment_number`

### 3.5 入口二：onCustomerChange(customer_id) — 负责发票列表刷新

**代码位置** [payments/Create.vue:L422-L484](file:///d:/fz/0601-1/solo-dogfeeding/code/22-InvoiceShelf/resources/scripts/admin/views/payments/Create.vue#L422-L484)

```javascript
function onCustomerChange(customer_id) {
  if (customer_id) {
    let data = {
      customer_id: customer_id,
      status: 'DUE',      // 新建模式：只拉"待付款"发票
      limit: 'all',
    }
    if (isEdit.value) {
      data.status = ''    // 编辑模式：不过滤状态
    }

    isLoadingInvoices.value = true

    Promise.all([
      invoiceStore.fetchInvoices(data),      // 拉取该客户的发票列表
      customerStore.fetchCustomer(customer_id),  // 拉取客户详情
    ])
      .then(async ([res1, res2]) => {
        // 1. 更新发票列表
        if (res1) {
          invoiceList.value = [...res1.data.data]
        }

        // 2. 更新客户信息和币种
        if (res2 && res2.data) {
          paymentStore.currentPayment.selectedCustomer = res2.data.data
          paymentStore.currentPayment.customer = res2.data.data
          paymentStore.currentPayment.currency = res2.data.data.currency
        }

        // 3. 如果原来已有选中的发票，尝试重新关联
        if (paymentStore.currentPayment.invoice_id) {
          selectedInvoice.value = invoiceList.value.find(
            (inv) => inv.id === paymentStore.currentPayment.invoice_id
          )
          paymentStore.currentPayment.maxPayableAmount =
            selectedInvoice.value.due_amount + paymentStore.currentPayment.amount

          if (amount.value === 0) {
            amount.value = selectedInvoice.value.due_amount / 100
          }
        }

        // 4. 编辑模式：过滤掉已付清的发票（除当前选中的）
        if (isEdit.value) {
          invoiceList.value = invoiceList.value.filter((v) => {
            return v.due_amount > 0 || v.id == paymentStore.currentPayment.invoice_id
          })
        }

        isLoadingInvoices.value = false
      })
  }
}
```

**核心职责**：
1. 拉取新客户的发票列表
2. 更新客户信息和币种
3. 尝试保留原有的发票选择（如果发票在新列表中存在）
4. 编辑模式下过滤已付清发票

### 3.6 双入口对比总结

| 维度 | selectNewCustomer | onCustomerChange |
|------|------------------|-----------------|
| **触发方式** | `@update:modelValue` 事件 | `watchEffect` 响应 `customer_id` 变化 |
| **触发时机** | 选择客户时立即执行 | `customer_id` 变化后异步执行 |
| **是否刷新编号** | ✅ 是（调用 `getNextNumber(params, true)`） | ❌ 否（只刷新发票列表） |
| **是否清空状态** | ✅ 清空发票、金额、列表 | ❌ 不清空，尝试保留原有选择 |
| **是否拉取发票** | ❌ 否 | ✅ 是（并行拉取发票和客户） |
| **是否更新币种** | ❌ 否 | ✅ 是（从客户信息获取） |
| **编辑模式处理** | ✅ 传 `model_id` 保留序号 | ✅ 不过滤发票状态 + 过滤已付清发票 |

### 3.7 潜在的竞态条件

由于两个函数并行执行，存在理论上的时序问题：
1. `selectNewCustomer` 先清空了 `invoice_id = null`
2. `onCustomerChange` 检查 `if (paymentStore.currentPayment.invoice_id)` 时条件不成立
3. 原有的发票选择丢失

这在**编辑模式**下可能导致用户已选的发票被意外清空。但实际测试中由于 `selectNewCustomer` 是同步执行清空，而 `onCustomerChange` 的 `.then()` 是异步的，该问题确实存在。

## 5. 完整串联步骤：从客户切换到编号写回

### 5.1 新建模式完整时间轴

```
T0 页面初始化
   │
   ├─ paymentStore.resetCurrentPayment()
   ├─ if (route.query.customer) 设置 customer_id
   └─ paymentStore.fetchPaymentInitialData(false)
        ├─ Promise.all([
        │    fetchPaymentModes(),
        │    getNextNumber(),          // setState=false，只请求不写回
        │  ])
        └─ .then() 中写回 payment_number
   ↓
T1 用户选择客户（customer_id: 1 → 2）
   │
   ├─ BaseCustomerSelectInput emit('update:modelValue', 2)
   │    │
   │    ├─ v-model: customer_id = 2
   │    │    │
   │    │    └─ watchEffect 触发 → onCustomerChange(2) 开始执行
   │    │          │
   │    │          ├─ isLoadingInvoices = true
   │    │          └─ Promise.all([
   │    │               fetchInvoices({ customer_id: 2, status: 'DUE' }),  ← 异步请求A
   │    │               fetchCustomer(2)                                 ← 异步请求B
   │    │             ])
   │    │
   │    └─ @update:modelValue 触发 → selectNewCustomer(2) 同步执行
   │          │
   │          ├─ invoice_id = null
   │          ├─ selectedInvoice = null
   │          ├─ amount = 0
   │          ├─ invoiceList = []
   │          └─ getNextNumber({ userId: 2 }, true)
   │                │
   │                └─ HTTP GET /api/v1/next-number?key=payment
   │                     └─ 后端返回 { nextNumber: 'PAY-2024-00042' }
   │                          └─ setState=true → payment_number = 'PAY-2024-00042'
   │
   └─ 此时并行执行中：
        │
        T2 onCustomerChange 的异步请求返回
        │   │
        │   ├─ invoiceList = [新客户的待付款发票列表]
        │   ├─ selectedCustomer = 客户2信息
        │   ├─ customer = 客户2信息
        │   ├─ currency = 客户2币种
        │   └─ 检查 invoice_id → 为 null，跳过重选逻辑
        │
        └─ T3 getNextNumber 请求返回，payment_number 更新为新编号
            └─ 用户看到编号已刷新，发票列表已更新
```

### 5.2 客户切换后的编号刷新后端逻辑

当前端调用 `getNextNumber({ userId: 2 }, true)` 时，后端执行流程：

**代码位置** [SerialNumberFormatter.php:L81-L102](file:///d:/fz/0601-1/solo-dogfeeding/code/22-InvoiceShelf/app/Services/SerialNumberFormatter.php#L81-L102)

```php
public function getNextNumber($data = null)
{
    $modelName = strtolower(class_basename($this->model));  // 'payment'
    $settingKey = $modelName.'_number_format';              // 'payment_number_format'

    // 从 CompanySetting 读取付款单编号格式
    $format = CompanySetting::getSetting($settingKey, $this->company);

    $this->setNextNumbers();  // 计算递增序号

    // 按格式拼装编号（含随机段）
    $serialNumber = $this->generateSerialNumber($format);

    return $serialNumber;
}
```

如果格式中包含 `CUSTOMER_SEQUENCE`，则会使用 `setCustomer(2)` 设置的客户来计算。

## 6. 编辑模式下的特殊行为差异

### 6.1 初始化差异

**新建模式**：
```javascript
paymentStore.fetchPaymentInitialData(false)
  → Promise.all([fetchPaymentModes, getNextNumber()])
  → .then() 中写回 payment_number
```

**编辑模式**：
```javascript
paymentStore.fetchPaymentInitialData(true)
  → Promise.all([fetchPaymentModes, getNextNumber(), fetchPayment(id)])
  → .then() 中完全不写回 payment_number，由 fetchPayment 的结果覆盖
```

**关键**：编辑模式下，`fetchPayment(id)` 返回的数据会覆盖初始化时获取的编号预览，确保显示数据库中的实际值。

### 6.2 客户切换差异

| 行为 | 新建模式 | 编辑模式 |
|------|---------|---------|
| `selectNewCustomer` 参数 | `{ userId: id }` | `{ userId: id, model_id: route.params.id }` |
| 后端 `setModelObject` | 不调用（无 model_id） | 调用 → 保留原有 `sequence_number` |
| `onCustomerChange` 发票状态过滤 | `status: 'DUE'`（只看未付款） | `status: ''`（不过滤） |
| `onCustomerChange` 已付清过滤 | 不过滤 | 过滤 `due_amount > 0 \|\| v.id == current_invoice_id` |

### 6.3 后端保存差异

**新建模式 - createPayment()** [Payment.php:L161-L203](file:///d:/fz/0601-1/solo-dogfeeding/code/22-InvoiceShelf/app/Models/Payment.php#L161-L203)：

```php
public static function createPayment($request)
{
    $data = $request->getPaymentPayload();  // payment_number 来自前端

    // 处理发票付款逻辑...

    $payment = Payment::create($data);  // 保存前端传来的 payment_number
    $payment->unique_hash = Hashids::encode($payment->id);

    // 后端独立计算序号
    $serial = (new SerialNumberFormatter)
        ->setModel($payment)
        ->setCompany($payment->company_id)
        ->setCustomer($payment->customer_id)
        ->setNextNumbers();  // 无 model_id，重新计算 MAX+1

    $payment->sequence_number = $serial->nextSequenceNumber;
    $payment->customer_sequence_number = $serial->nextCustomerSequenceNumber;
    $payment->save();

    return $payment;
}
```

**编辑模式 - updatePayment()** [Payment.php:L205-L255](file:///d:/fz/0601-1/solo-dogfeeding/code/22-InvoiceShelf/app/Models/Payment.php#L205-L255)：

```php
public function updatePayment($request)
{
    $data = $request->getPaymentPayload();

    // 处理发票付款变更逻辑...

    $serial = (new SerialNumberFormatter)
        ->setModel($this)
        ->setCompany($this->company_id)
        ->setCustomer($request->customer_id)
        ->setModelObject($this->id)  // ← 关键：传入现有单据ID
        ->setNextNumbers();          // 内部会保留原有 sequence_number

    // 只可能更新 customer_sequence_number（客户变化时）
    // sequence_number 永远不变
    $data['customer_sequence_number'] = $serial->nextCustomerSequenceNumber;
    $this->update($data);

    return $payment;
}
```

### 6.4 编辑模式下序号保留的完整逻辑

**代码位置** [SerialNumberFormatter.php:L43-L56](file:///d:/fz/0601-1/solo-dogfeeding/code/22-InvoiceShelf/app/Services/SerialNumberFormatter.php#L43-L56)

```php
public function setModelObject($id = null)
{
    $this->ob = $this->model::find($id);

    // sequence_number 无条件保留（如果已有）
    if ($this->ob && $this->ob->sequence_number) {
        $this->nextSequenceNumber = $this->ob->sequence_number;
    }

    // customer_sequence_number 仅在客户未变化时保留
    if (isset($this->ob)
        && isset($this->ob->customer_sequence_number)
        && isset($this->customer)
        && $this->ob->customer_id == $this->customer->id) {  // ← 客户相同才保留
        $this->nextCustomerSequenceNumber = $this->ob->customer_sequence_number;
    }

    return $this;
}
```

**编辑模式下切换客户的结果**：
- `sequence_number`：**保持不变**（例如原来的 42）
- `customer_sequence_number`：**重新计算**（新客户的 MAX+1）
- `payment_number`：前端 `selectNewCustomer` 中已刷新
- `unique_hash`：**永不变化**（绑定自增 ID）

public function getPaymentPayload()

## 8. 发现的问题与改进建议

### 8.1 双入口并行执行的竞态问题

**问题**：`selectNewCustomer` 先同步清空 `invoice_id = null`，随后 `onCustomerChange` 的异步回调检查 `if (invoice_id)` 时条件不成立，导致编辑模式下原有发票选择丢失。

**建议**：
1. 将清空逻辑移到 `onCustomerChange` 的 `.then()` 中，或
2. 在 `selectNewCustomer` 中暂存原 `invoice_id`，在 `onCustomerChange` 中恢复

### 8.2 付款单与发票/报价单的行为不一致

发票和报价单的客户切换在 BaseCustomerSelectPopup 中统一处理，只会调用一次 `getNextNumber(params, true)`，没有 `watchEffect` 二次触发。付款单的双入口设计增加了复杂度。

**建议**：统一使用 BaseCustomerSelectPopup 模式，移除付款单的 `watchEffect` 独立触发逻辑。

### 8.3 新建模式下 maxPayableAmount 的初始值问题

初始值为 `Number.MAX_SAFE_INTEGER`，在未选择发票时金额校验的上限过大。

**建议**：未选择发票时禁用金额输入框，或设置合理的默认上限。

---

## 9. 总结

### 9.1 客户切换触发机制

付款单采用 **双入口并行触发**：
- **selectNewCustomer(id)**：由 `@update:modelValue` 事件触发，负责**清空状态 + 刷新编号**
- **onCustomerChange(customer_id)**：由 `watchEffect` 响应式触发，负责**拉取发票列表 + 更新客户信息**

两者并行执行，各司其职。

### 9.2 选中发票后的状态更新

`onSelectInvoice(id)` 会更新四个关键状态：
1. `selectedInvoice.value` — 完整发票对象
2. `amount.value` — 显示金额（元）
3. `paymentStore.currentPayment.amount` — 存储金额（分，通过 computed setter 同步）
4. `paymentStore.currentPayment.maxPayableAmount` — 最大可付金额（用于校验）

### 9.3 完整串联步骤

```
选择客户
  ├─→ customer_id 更新
  │     ├─→ watchEffect → onCustomerChange（异步拉发票+客户）
  │     └─→ @update:modelValue → selectNewCustomer（同步清空+刷新编号）
  └─→ 异步返回后：
        ├─ invoiceList 更新
        ├─ customer/currency 更新
        └─→ 用户选择发票 → onSelectInvoice → 更新金额和最大可付
```

### 9.4 编辑模式差异

| 字段 | 新建模式 | 编辑模式 |
|------|---------|---------|
| `payment_number` | 初始化时写回 | 由 fetchPayment 覆盖 |
| `sequence_number` | 后端重新计算 MAX+1 | 通过 `setModelObject(id)` 保留 |
| `customer_sequence_number` | 后端重新计算 | 客户变化时重算，不变时保留 |
| 发票列表过滤 | `status: 'DUE'` | 不过滤状态 + 过滤已付清 |
| `getNextNumber` 参数 | `{ userId }` | `{ userId, model_id }` |
