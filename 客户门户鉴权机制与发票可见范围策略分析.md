# InvoiceShelf 客户门户鉴权机制与发票可见范围策略分析

## 一、客户身份与系统用户的区别

### 1.1 模型定义差异

**系统用户（User）** - `app/Models/User.php`
- 继承自 `Authenticatable`，用于管理端认证
- 使用 `users` 表存储
- 拥有角色权限系统（Bouncer）
- 通过 `web` / `api` guard 进行认证
- 可关联多个公司，拥有管理功能权限

**客户（Customer）** - `app/Models/Customer.php:19`
```php
class Customer extends Authenticatable implements HasMedia
{
    use HasApiTokens;
    use HasRolesAndAbilities;
    use Notifiable;
    // ...
}
```
- 独立的 `Authenticatable` 实现，用于客户门户认证
- 使用 `customers` 表存储
- 拥有 `enable_portal` 字段控制门户访问权限
- 通过 `customer` guard 进行认证
- 属于单个公司（`company_id` 外键）

### 1.2 核心字段对比

| 特性 | 系统用户 (User) | 客户 (Customer) |
|------|----------------|----------------|
| 认证 Guard | `web` / `api` | `customer` |
| 密码字段 | `password` | `password` |
| 公司关联 | 多对多 (`company_user`) | 一对多 (`company_id`) |
| 门户开关 | 无 | `enable_portal` (boolean) |
| 角色系统 | Bouncer 完整权限 | Bouncer (主要用于区分) |
| 主要用途 | 后台管理 | 客户门户自助服务 |

```php
public function handle(Request $request, Closure $next): Response
{
    $user = Auth::guard('customer')->user();

    if (! $user->enable_portal) {
        Auth::guard('customer')->logout();
        return response('Unauthorized.', 401);
    }

    return $next($request);
}
```
- **作用**：检查客户是否被授权访问门户
- **逻辑**：验证 `enable_portal` 字段，未启用则强制登出

### 2.3 登录流程

**登录控制器** - `app/Http/Controllers/V1/Customer/Auth/LoginController.php:21-44`
```php
public function __invoke(CustomerLoginRequest $request, Company $company)
{
    // 1. 按邮箱+公司查找客户
    $user = Customer::where('email', $request->email)
        ->where('company_id', $company->id)
        ->first();

    // 2. 验证密码
    if (! $user || ! Hash::check($request->password, $user->password)) {
        throw ValidationException::withMessages([
            'email' => ['The provided credentials are incorrect.'],
        ]);
    }

    // 3. 检查门户是否启用
    if (! $user->enable_portal) {
        throw ValidationException::withMessages([
            'email' => ['Customer portal not available for this user.'],
        ]);
    }

    // 4. 使用 customer guard 登录
    Auth::guard('customer')->login($user);

    return response()->json(['success' => true]);
}
```

#### 列表查询
```php
public function index(Request $request)
{
    $limit = $request->has('limit') ? $request->limit : 10;

    $invoices = Invoice::with(['items', 'customer', 'creator', 'taxes'])
        ->where('status', '<>', 'DRAFT')                    // 1. 排除草稿
        ->applyFilters($request->all())                     // 2. 应用其他过滤
        ->whereCustomer(Auth::guard('customer')->id())      // 3. 客户隔离
        ->latest()
        ->paginateData($limit);

    return InvoiceResource::collection($invoices)
        ->additional(['meta' => [
            'invoiceTotalCount' => Invoice::where('status', '<>', 'DRAFT')
                ->whereCustomer(Auth::guard('customer')->id())
                ->count(),
        ]]);
}
```

#### 详情查询
```php
public function show(Company $company, $id)
{
    $invoice = $company->invoices()
        ->whereCustomer(Auth::guard('customer')->id())  // 客户隔离
        ->where('id', $id)
        ->first();

    if (! $invoice) {
        return response()->json(['error' => 'invoice_not_found'], 404);
    }

    return new InvoiceResource($invoice);
}
```

## 四、鉴权与可见性架构总结

### 4.1 完整调用链

```
客户端请求
    ↓
[路由层] /{company:slug}/customer/invoices
    ↓
[中间件层] 
    ├─ auth:customer → 验证客户登录状态
    └─ customer-portal → 检查 enable_portal 字段
    ↓
[控制器层] InvoicesController@index
    ├─ 排除 DRAFT 状态
    ├─ applyFilters() 应用查询过滤
    └─ whereCustomer(Auth::guard('customer')->id())
    ↓
[模型层] Invoice::scopeWhereCustomer()
    └─ where('invoices.customer_id', $customer_id)
    ↓
返回过滤后的结果集
```

### 4.2 安全设计要点

1. **Guard 隔离**：客户与系统用户使用独立的认证 guard，避免越权
2. **双重检查**：登录时 + 每次请求都检查 `enable_portal` 状态
3. **多层过滤**：公司 → 客户 → 状态，三层可见性控制
4. **关系查询**：使用 `$company->invoices()` 而非 `Invoice::query()`，强制公司范围
5. **显式过滤**：每个查询都显式调用 `whereCustomer()`，不依赖全局 Scope

## 五、扩展与维护建议

1. **性能优化**：`customer_id` 字段已建立外键，查询性能有保障
2. **审计日志**：建议在关键操作（如查看发票、在线支付）时增加审计日志
3. **缓存策略**：对于频繁查询的 Dashboard 数据，可考虑增加缓存层
4. **权限细化**：如需支持客户多角色，可扩展 Bouncer 权限配置
5. **API 版本**：当前使用 v1 路径，后续升级时需保持向后兼容
